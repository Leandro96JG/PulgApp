# Pulgapp Protocol V1

This document is normative. V1 uses JSON over WebSocket for control and a fixed 60-byte little-endian UDP datagram for input.

## Endpoints And Limits

- HTTP health: `GET http://HOST:26760/health`
- Control: `ws://HOST:26760/control`
- Input: UDP port `26761`
- IPv4 only in v1.
- Maximum WebSocket message size: 4096 UTF-8 bytes.
- One JSON object per WebSocket message.
- Unknown JSON fields are ignored; missing or invalid required fields are rejected.
- UDP input has no TCP/WebSocket fallback.

## Identifiers And Secrets

- `clientId`: persistent UUID generated by the mobile app.
- `serverId`: persistent UUID generated by the Windows app.
- `sessionId`: random nonzero 64-bit value, represented in JSON as exactly 16 lowercase hexadecimal characters.
- `udpToken`: 16 random bytes, Base64URL without padding in JSON.
- `resumeToken`: 32 random bytes, Base64URL without padding in JSON.
- `pin`: exactly six decimal characters, including possible leading zeroes.

Do not log the PIN, UDP token, or resume token. A resumed session keeps its target and slot but receives fresh session, UDP, and resume credentials.

## Canonical Gamepad State

- Stick values are signed 16-bit integers.
- Positive X is right.
- Positive Y is up.
- Trigger values are unsigned 16-bit integers from released `0` to fully pressed `65535`.
- Every input packet contains the complete state.

Button bits:

| Bit | Canonical | X360 | DS4 |
|---:|---|---|---|
| 0 | A | A | Cross |
| 1 | B | B | Circle |
| 2 | X | X | Square |
| 3 | Y | Y | Triangle |
| 4 | LB | Left Shoulder | L1 |
| 5 | RB | Right Shoulder | R1 |
| 6 | BACK | Back | Share |
| 7 | START | Start | Options |
| 8 | L3 | Left Thumb | L3 |
| 9 | R3 | Right Thumb | R3 |
| 10 | GUIDE | Guide | PS |
| 11 | DPAD_UP | Up | Hat North |
| 12 | DPAD_DOWN | Down | Hat South |
| 13 | DPAD_LEFT | Left | Hat West |
| 14 | DPAD_RIGHT | Right | Hat East |
| 15 | TOUCHPAD_CLICK | Ignored | Touchpad |
| 16-31 | Reserved | Ignored | Ignored |

If Up and Down are both set, clear both. If Left and Right are both set, clear both. Preserve all non-D-pad buttons.

## Control Messages

Every message has integer `v: 1` and string `type`.

### New Connection

Client to server:

```json
{
  "v": 1,
  "type": "hello",
  "clientId": "263b2310-4e1a-48df-8836-c5600ac77719",
  "clientName": "Pixel 8",
  "appVersion": "0.1.0",
  "pin": "482913",
  "capabilities": ["udp_input_v1", "rumble_v1"]
}
```

Required: `clientId`, nonblank `clientName` up to 64 Unicode scalar values, nonblank `appVersion` up to 32 characters, `pin`, and `capabilities`. Reject a message containing both `pin` and `resumeToken`.

The server validates credentials, atomically allocates a slot, creates and connects the target, and only then replies:

```json
{
  "v": 1,
  "type": "welcome",
  "serverId": "65fd878c-6001-45ee-b20d-24e471e4fa5b",
  "serverName": "Living Room PC",
  "sessionId": "0123456789abcdef",
  "udpToken": "ABEiM0RVZneImaq7zN3u_w",
  "udpPort": 26761,
  "slot": 1,
  "controllerType": "x360",
  "resumed": false,
  "resumeToken": "jP5dP4vJxPgmO8OpH4zgwAjiyXOSe3JvIwQfKHctnzM",
  "inputTimeoutMs": 250,
  "slotLeaseMs": 15000
}
```

`slot` is integer 1-8. `controllerType` is `x360` for slots 1-4 and `ds4` for slots 5-8.

### Resume

Client sends the same `hello` shape but omits `pin` and includes `resumeToken`. `clientId` must match the lease owner. A successful reply sets `resumed` to true and contains fresh credentials.

### UDP Ready

After the first accepted datagram, server sends once:

```json
{"v":1,"type":"input_ready","sequence":0}
```

If the client does not receive this within two seconds of `welcome`, it reports UDP as unavailable while keeping the control error visible.

### Ping And Pong

Client sends every two seconds:

```json
{"v":1,"type":"ping","id":42,"clientTimeUs":"123456789"}
```

Server responds immediately:

```json
{"v":1,"type":"pong","id":42,"clientTimeUs":"123456789","serverReceiveTimeUs":"9087211241","serverSendTimeUs":"9087211298"}
```

`id` is uint32 represented as a JSON number. Monotonic 64-bit times are decimal strings and are diagnostic only.

### Input Status

```json
{"v":1,"type":"input_status","state":"timed_out","lastSequence":42}
```

Valid states are `ready`, `timed_out`, and `restored`. `lastSequence` is nullable before any accepted datagram.

### Leave And Suspend

```json
{"v":1,"type":"leave"}
```

`leave` neutralizes, disconnects, invalidates credentials, and frees the slot immediately.

```json
{"v":1,"type":"suspend"}
```

`suspend` neutralizes immediately and starts the 15-second lease. The client then closes normally.

### Optional Rumble

Server to client, only when the capability was offered:

```json
{"v":1,"type":"rumble","lowFrequency":180,"highFrequency":64}
```

Values are uint8. Rumble is not required before phase P5 and must never delay input handling.

### Error

```json
{
  "v": 1,
  "type": "error",
  "code": "invalid_pin",
  "message": "The PIN is invalid.",
  "fatal": true,
  "retryAfterMs": 30000
}
```

Required codes: `protocol_mismatch`, `invalid_pin`, `rate_limited`, `server_full`, `driver_unavailable`, `controller_create_failed`, `client_already_connected`, `resume_rejected`, `malformed_message`, `udp_unavailable`, and `server_shutting_down`.

`retryAfterMs` is optional. Fatal errors are followed by a close frame.

Close codes:

| Code | Meaning |
|---:|---|
| 1000 | Normal leave, suspend, or shutdown acknowledgement |
| 1002 | Malformed or unsupported protocol |
| 1008 | Invalid PIN or token |
| 1011 | Internal or driver failure |
| 1013 | Full or temporarily unavailable server |

## UDP Input Datagram

Exactly 60 bytes, little-endian:

| Offset | Size | Type | Field | Validation |
|---:|---:|---|---|---|
| 0 | 4 | bytes | Magic | ASCII `PULG` |
| 4 | 1 | uint8 | Version | `1` |
| 5 | 1 | uint8 | Packet type | `1` input snapshot |
| 6 | 2 | uint16 | Flags | `0` in v1 |
| 8 | 8 | uint64 | Session ID | Active session |
| 16 | 16 | bytes | UDP token | Constant-time equality |
| 32 | 4 | uint32 | Sequence | Newer modulo 2^32 |
| 36 | 8 | uint64 | Client monotonic microseconds | Diagnostic only |
| 44 | 4 | uint32 | Buttons | Complete bitfield |
| 48 | 2 | int16 | Left X | Complete value |
| 50 | 2 | int16 | Left Y | Positive up |
| 52 | 2 | int16 | Right X | Complete value |
| 54 | 2 | int16 | Right Y | Positive up |
| 56 | 2 | uint16 | Left trigger | `0..65535` |
| 58 | 2 | uint16 | Right trigger | `0..65535` |

Accept sequence `candidate` after `previous` only when signed 32-bit reinterpretation of `candidate - previous` is greater than zero. A fresh session has no previous sequence and accepts any first sequence.

The server silently discards invalid UDP packets. It increments aggregate diagnostics but does not send per-packet errors or logs.

Validate the source IPv4 against the WebSocket peer. Do not bind authentication to the client's UDP source port; mobile operating systems may recreate the socket.

## Send And Timeout Policy

- Send a changed snapshot immediately when at least 8 ms elapsed since the previous send.
- Coalesce newer changes inside that interval.
- Send unchanged state every 50 ms.
- Send neutral immediately after `welcome`.
- On pointer cancellation, lifecycle pause, or controller-screen exit, clear local state and send neutral three times at 10 ms intervals before suspending when possible.
- Neutralize the target after 250 ms without an accepted UDP datagram.
- WebSocket loss neutralizes immediately and starts a 15-second lease.

## Driver Mapping

X360 stick values are copied as signed shorts. Trigger byte is rounded from uint16 to `0..255`. Canonical Y is not inverted.

DS4 axis byte conversion uses the whole signed range. X maps negative to 0 and positive to 255. Y is inverted so positive canonical Y maps toward DS4 byte 0. Neutral maps to approximately 128. Trigger byte is rounded to `0..255`; set the corresponding digital L2/R2 button whenever the converted trigger is nonzero.

For both adapters, disable automatic report submission, modify every report field from the complete canonical state, and submit exactly once.

## Golden Fixture

`protocol/fixtures/input-state-v1.json` describes the semantic values. `input-state-v1.hex` is the canonical byte sequence. `input-state-v1.bin` must contain the identical 60 bytes before codec implementation starts.
